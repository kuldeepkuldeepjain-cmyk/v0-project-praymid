================================================================================
OVERVIEW
================================================================================

When a participant registers:
  • They immediately receive $50 "unclaimed bonus"
  • The bonus is marked as unclaimed until they contribute
  • When they make their first contribution, bonus is automatically claimed
  • The $50 is added to their account balance

================================================================================
KEY FLOWS
================================================================================

FLOW 1: Registration → Bonus Granted
────────────────────────────────────
  User clicks "Register"
    ↓
  Submits: firstName, lastName, email, password, mobile, etc.
    ↓
  System creates participant with:
    • account_balance: 0
    • unclaimed_bonus: 50
    • bonus_claimed: false
    ↓
  Response shows: "Welcome bonus: $50 (claim by making your first contribution)"
    ↓
  User logs in → Dashboard shows unclaimed bonus card


FLOW 2: Dashboard Display
─────────────────────────
  Participant views dashboard
    ↓
  Query returns:
    • Wallet Balance: $0
    • unclaimed_bonus: 50
    • bonus_claimed: false
    ↓
  UI renders yellow "Unclaimed Welcome Bonus" card with $50 and button
    ↓
  User clicks "Start Contributing" → redirects to /participant/dashboard/contribute


FLOW 3: Contribution & Auto-Claim
──────────────────────────────────
  User submits payment proof
    ↓
  Admin receives notification and reviews payment
    ↓
  Admin clicks "Confirm" in admin panel
    ↓
  Payment status updated to "confirmed"
    ↓
  System triggers automatic bonus claim:
    • Adds $50 to account_balance
    • Sets bonus_claimed = true
    • Sets bonus_claimed_at = NOW()
    • Creates transaction record (type: bonus_claim)
    ↓
  Participant's balance: $250 ($200 contribution reward + $50 bonus)
    ↓
  Dashboard refreshes → Unclaimed bonus card disappears
    ↓
  User sees: "Wallet Balance: $250.00"


FLOW 4: Already-Contributed Users
──────────────────────────────────
  User who already contributed before this feature:
    ↓
  Migration script checks: Has made payment submission?
    ↓
  If YES: Does NOT get $50 bonus (bonus_claimed = true, unclaimed_bonus = 0)
    ↓
  If NO: Gets $50 bonus (unclaimed_bonus = 50, bonus_claimed = false)

DATABASE CHANGES
================================================================================

New Columns on 'participants' table:
┌─────────────────────────┬──────────────┬─────────────────┐
│ Column Name             │ Type         │ Default         │
├─────────────────────────┼──────────────┼─────────────────┤
│ unclaimed_bonus         │ NUMERIC      │ 0               │

│ bonus_claimed_at        │ TIMESTAMP    │ NULL            │
└─────────────────────────┴──────────────┴─────────────────┘

New Indexes:
  • idx_participants_unclaimed_bonus
    └─ For fast queries: WHERE unclaimed_bonus > 0 AND bonus_claimed = FALSE

  • idx_participants_bonus_claimed
    └─ For tracking: WHERE bonus_claimed = TRUE

New Transaction Type:
  • type = 'bonus_claim'
  • Logged when bonus is claimed
  • Includes: amount ($50), balance before/after

ROLLBACK PROCEDURE
================================================================================

If needed to rollback:

1. Drop the new columns:
   ALTER TABLE participants
     DROP COLUMN IF EXISTS unclaimed_bonus,
     DROP COLUMN IF EXISTS bonus_claimed,
     DROP COLUMN IF EXISTS bonus_claimed_at;

2. Drop the indexes:
   DROP INDEX IF EXISTS idx_participants_unclaimed_bonus;
   DROP INDEX IF EXISTS idx_participants_bonus_claimed;

3. Revert code to previous version
4. Redeploy application

Note: This doesn't delete existing transactions, just removes the tracking.
